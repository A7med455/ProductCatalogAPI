# Product Catalog API

A simple CRUD (Create, Read, Update, Delete) product catalog API built with **ASP.NET Core**. This project demonstrates a layered architecture using Controllers, Services, and Models, with an in-memory data store.

## Features

- Full CRUD operations for managing products
- Layered architecture: Controller → Service (via interface) → Model
- Dependency Injection for loose coupling between controller and service
- In-memory data storage (no database required)
- Tested manually with Postman

## Tech Stack

- **Framework:** ASP.NET Core Web API
- **Language:** C#
- **Testing tool:** Postman

## Project Structure

```
productCatalogAPI/
├── Controllers/
│   └── ProductsController.cs   # HTTP endpoints (GET, POST, PUT, DELETE)
├── Models/
│   └── Product.cs              # Product data model
├── Services/
│   ├── IProductService.cs      # Service contract/interface
│   └── ProductService.cs       # CRUD logic + in-memory product list
├── Program.cs                  # App startup & dependency injection setup
└── README.md
```

## Product Model

| Property    | Type    |
|-------------|---------|
| Id          | int     |
| Name        | string  |
| Description | string? |
| Price       | double  |

## API Endpoints

Base route: `api/products`

| Method | Endpoint            | Description                     |
|--------|----------------------|----------------------------------|
| GET    | `/api/products`      | Get all products                |
| GET    | `/api/products/{id}` | Get a single product by ID      |
| POST   | `/api/products`      | Create a new product            |
| PUT    | `/api/products/{id}` | Update an existing product      |
| DELETE | `/api/products/{id}` | Delete a product by ID          |

## Getting Started

### Prerequisites

- [.NET SDK](https://dotnet.microsoft.com/download) installed

### Run the project

```bash
git clone https://github.com/A7med455/product-catalog-api.git
cd product-catalog-api
dotnet run
```

The API will start on a local port (shown in the terminal, e.g. `http://localhost:5282`).

## Testing with Postman

All endpoints were manually tested using **Postman**. Below is the request setup for each operation.

### 1. Get all products

- **Method:** `GET`
- **URL:** `http://localhost:5282/api/products`
- **Body:** none

### 2. Get product by ID

- **Method:** `GET`
- **URL:** `http://localhost:5282/api/products/1`
- **Body:** none
- Returns `404 Not Found` if the ID doesn't exist

### 3. Create a product

- **Method:** `POST`
- **URL:** `http://localhost:5282/api/products`
- **Body:** raw → JSON

```json
{
  "name": "Keyboard",
  "description": "Mechanical keyboard",
  "price": 1200
}
```

The `Id` is auto-generated by the service — no need to include it in the request.

### 4. Update a product

- **Method:** `PUT`
- **URL:** `http://localhost:5282/api/products/1`
- **Body:** raw → JSON

```json
{
  "name": "Gaming Laptop Pro",
  "description": "Updated description",
  "price": 30000
}
```

### 5. Delete a product

- **Method:** `DELETE`
- **URL:** `http://localhost:5282/api/products/2`
- **Body:** none

## Notes

- Data is stored **in memory**, meaning it resets every time the application restarts (no database is connected in this version).
- Product IDs are auto-generated by taking the current highest ID in the list and adding 1.
